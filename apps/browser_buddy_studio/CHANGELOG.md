# BrowserBuddy Changelog

## 2.4.1 — 2026-11-11

### 修复回复语言

- 英文消息不再因为提示词里的中文脚手架而返回中文。例如输入 `hi` 现在会得到英文回复。
- 聊天提示、附件说明、会话摘要和上下文标签会按当前消息语言选择中文或英文。
- 浏览器任务的历史上下文、附件说明和视觉模式提示也会跟随任务语言。
- 英文任务会明确要求最终答案使用英文；中文任务仍然保持中文。
- 语言判断会把「打开 taobao」「iPhone 怎么连接」这类中英混合消息识别为中文，而把英文句子中顺带提到的中文网站名识别为英文。

## 2.4.0 — 2026-11-11

### 中英双语界面

- 新增界面语言切换：中文 / English。
- 设置 → 外观下方新增「语言」区域，切换后立即生效并持久化。
- 首次启动跟随系统语言：中文系统显示中文，其他系统显示英文。
- 已翻译主要界面：
  - 侧边栏、历史对话、删除确认
  - 新对话、输入框、附件、发送/停止
  - 设置面板、语言、主题、数据与卸载
  - 登录平台、人工验证、登录状态
  - 结果区、来源、执行轨迹、附件与图片
  - 常见错误提示、toast、上下文提醒
  - 示例任务列表
- 后端常见错误增加英文映射，例如缺少 API Key、未找到浏览器、上下文超限、上传限制等。
- 英文界面下，示例任务也会切换为英文 prompt。

### 说明

- 用户自己的任务内容、上传文件内容和模型输出不会被强制翻译。
- 第三方平台名称（淘宝、京东、小红书、抖音）保留中文/英文品牌写法。
- 该版本为 App Store 发布做语言准备；上架还需要 App Sandbox、签名/公证、隐私说明和商店本地化元数据。

## 2.3.1 — 2026-11-11

本次更新主要集中在三件事：**多轮上下文更省 token、附件理解更完整、任务判断和状态提示更准确**。

### 多轮上下文与 Token 控制

- 较早的对话轮次会压缩成摘要，最近 4 轮保留原文，避免把整段历史直接塞给模型。
- 当前任务会被单独标记为唯一执行目标，历史信息只用于理解“继续”“这个”“上面那个”等指代。
- 对话长度提醒改为按模型上下文窗口计算，不再使用固定 20 轮限制。
  - 60%：轻提示
  - 80%：建议新建对话
  - 95%：强提示，继续可能触发模型窗口限制
- 支持在设置中手动填写上下文窗口大小；各 provider 也提供默认值。
- 当真实请求超过模型窗口时，会返回中文提示并建议新建对话，而不是直接抛出原始英文异常。
- 输入框单条消息最多 8000 字符，超过 2000 字符开始显示计数。

### 意图判断与加载状态

- 前端不再自行判断任务类型，统一由后端决定。
- 后端只保留两个高置信度快捷判断：
  - 文本中出现 URL → 浏览器任务
  - 纯问候 / 感谢 / 身份问题 → 聊天任务
- 其他复杂或模糊请求全部交给 LLM 判断，避免“解释一下搜索原理”因为包含“搜索”而误开浏览器。
- LLM 判断失败时，才回退到强浏览器动词（打开、访问、登录、下载、上传等）。
- 加载文案改为：
  - 判断前：`正在分析任务...`
  - 浏览器任务：`正在启动浏览器...`
  - 聊天任务：`正在处理任务...`

### 文件、图片与视频附件

- 支持最多 10 个附件，单次总大小 300 MB。
- 分类型限制：
  - 图片：20 MB
  - 视频：200 MB
  - PDF / Word / PPT：100 MB
  - Excel / CSV：50 MB
  - 普通文本：20 MB
- 上传改为流式写盘，不再把整个大文件读进内存。
- 文本类附件自动提取内容：
  - TXT / Markdown / CSV / JSON / YAML / 代码文件
  - HTML
  - PDF
  - DOCX
- Excel / PPT 目前允许上传，但暂不解析文本内容。
- 原始文件路径会加入 Agent 的 `available_file_paths`，可用于读取或上传到网站。
- 多附件提示词会明确列出文件数量，并要求逐个说明，避免只回答其中一个。

### 图片理解

- 图片会作为真正的 image content 传给 Vision LLM，而不是只做 OCR 或文字描述。
- Agent 模式通过 `sample_images` 传图，聊天模式通过 image parts 传图。
- 图片自动压缩到最长边 1280px，透明图保留 PNG，其余转 JPEG。
- 设置中可开关「视觉模式」；关闭时会提示图片无法被模型理解。
- 上传界面和对话消息中会显示图片缩略图。

### 视频理解

- 支持 MP4 / MOV / M4V / WebM / AVI / MKV。
- App 内置 ffmpeg（`imageio-ffmpeg`），目标 Mac 不需要单独安装。
- 关键帧数量按时长自适应：
  - ≤ 30 秒：6 帧
  - 30 秒 – 2 分钟：8 帧
  - 2 – 10 分钟：12 帧
  - 10 – 30 分钟：16 帧
  - > 30 分钟：20 帧
- 聊天模式最多使用 20 帧；浏览器 Agent 每步都会带图，限制为 8 帧以控制 token。
- 音频轨道会被提取并转写：
  - 优先使用当前 OpenAI / Google Gemini provider
  - 否则复用已保存的 OpenAI 或 Gemini Key
  - 都没有时提示“未配置音频转录 Key”
  - 最多转写前 30 分钟
  - 转录结果缓存，后续不重复收费
- 视频会生成一份内容摘要并缓存，后续对话只带摘要，不再重复发送关键帧和完整转录。

### 附件摘要缓存

- 图片、文档、视频都会在第一次处理时生成摘要，缓存到附件目录的 `summary.txt`。
- 短文本（≤ 1200 字）直接缓存原文，不调用 LLM。
- 长文档、图片、视频使用 LLM 生成 300–500 字摘要，尽量保留实体、数字、条件、结论和关键细节。
- 后续对话引用附件时，只把摘要加入上下文，不再重复发送全文、图片、关键帧或转录。
- 历史轮次继续变旧时，摘要会进一步进入会话摘要，避免 context 膨胀。

### 对话与数据清理

- 侧边栏支持删除单条对话：
  - 鼠标悬停显示垃圾桶
  - 二次确认
  - 任务运行中禁止删除
- 删除对话时会清理：
  - `chats.json` 中的对话记录
  - legacy `history.json` 中的对应记录
  - 内存中的上下文摘要缓存
  - 该对话独占的 artifacts
  - 该对话独占的上传文件
- artifacts 和 uploads 都做了引用计数，多个对话共用的文件不会被误删。
- 删除后 toast 会显示清理了多少附件/上传文件。

### 稳定性与浏览器修复

- 修复 Chrome 被强制结束后 profile 一直标记为 `Crashed` 的问题。
  - 现在会写入 `exit_type=Normal`
  - `restore_on_startup=5`
  - 清空 `startup_urls`
  - 避免下次启动恢复旧任务标签页
- 收紧链接打开范围：只有聊天内容区域的链接才会被拦截打开，点击侧边栏对话不再触发链接处理。
- `/api/open-url` 增加来源日志，便于排查“莫名打开旧页面”的问题。
- 修复 `platform_logins.py` 的类型问题，`pre-commit`（ruff、pyright、codespell 等）全部通过。

### 当前限制

- 视频理解是“关键帧 + 音频转录”，不是原生视频输入；长视频可能漏掉短暂画面。
- 音频转录需要 OpenAI 或 Google Gemini Key；只有 DeepSeek Key 时只能分析画面。
- Excel / PPT 暂不解析文本。
- 扫描版 PDF 没有文本层，暂时无法提取内容。
- 摘要有损；后续追问非常细的细节时，可能不在摘要里。
- 暂不支持原生生成图片或视频。

### 升级说明

- 已安装版本：**2.3.1**

- 新增的摘要、转录和关键帧缓存会在首次使用对应附件时生成。
